BizSim 团队分工讲解版

这不是一份“大家都做一点”的泛化分工，而是一条从输入 → Seed → Agent → 模拟 → 报告 → 展示的明确接棒链。 Weiyou 把商业想法转成可模拟对象并定义商业语义，曲良负责 OASIS 的拓扑、推荐与运行机制，Chris 保证全局工程骨架稳定，Zhidong 把结果变成可解释、可展示的产品表面，Yifu 负责方向、节奏与对外讲述。

团队规模 5 人
关键接口 7 个
主要里程碑 3 段
当前重点 Phase 1 收口

建议讲解顺序

  1. 先讲“为什么不是平均分工”，而是围绕一条主管线分工。
  2. 再讲 5 个人分别站在管线的什么位置、谁接谁的棒。
  3. 然后讲 7 个关键接口，解释为什么接口比人更多地决定协作效率。
  4. 最后讲 6 周节奏和 3 个主要风险，让团队知道近期重点。

00 / Framing

为什么这份分工更适合当前 BizSim

现在 BizSim 不是在做一个“大而全的平台”，而是在用 Business Validation 这个切入口，先做出一条最小但完整的产品链路。

原则一：围绕主链路拆人

主链路是输入、生成、模拟、报告与展示，不是按“前后端”“算法”“产品”这种传统标签平均切分。

原则二：接口比职位更重要

I3、I4、I5 是最关键的三个接口：Agent 池、状态机事件、Trace schema；而 I6 负责把 Weiyou 的商业语义和 Zhidong 的报告框架对齐。

原则三：管理和技术都横切

Yifu 负责产品方向和节奏，Chris 负责工程骨架和技术翻译。一个管“要什么”，一个管“怎么做”。

01 / Pipeline

从商业想法到报告输出，谁在什么时候接棒

这张图建议先看中间实线主流程，再看上方的管理支撑线和下方的技术支撑线。图里只保留短标签，详细说明放在右侧。

图中节点说明

  • 入口前端：Wizard / Project Detail，负责把用户输入变成结构化场景。
  • Seed 生成：市场上下文、竞品概览、消费者画像、讨论话题。
  • Agent 池生成：角色分布、人设 prompt、三层分级、行为先验、商业语义动作。
  • 模拟引擎：OASIS 适配、推荐算法、交互拓扑、事件流。
  • Trace / 事件：运行日志、轮次事件、指标更新。
  • 报告与可解释：执行摘要、Lean Canvas、SWOT、PMF、风险清单、行为归因。

怎么讲这张图

  1. 先讲中间实线：这是 BizSim 最小闭环。
  2. 再讲 Weiyou 和曲良的边界：Weiyou 定义商业语义动作，曲良负责这些动作如何在拓扑里被推荐、传播和记录。
  3. 再讲上方 Yifu：不做技术实现，但负责方向、优先级和对外讲法。
  4. 最后讲下方 Chris：所有模块都要落到统一架构里，所以 Chris 是技术中枢。
02 / Roles

五人分工总览

每个人都围绕一个清晰的“输入—输出”责任段工作，减少模糊重叠，避免多人同时碰同一个问题。

Yifu PM / 产品决策
负责“方向和节奏”，不负责具体技术实现。

Yifu 的核心价值不在写代码，而在于让团队知道现在最该做什么、什么时候切换优先级、怎么对外讲清楚。

主要负责

  • 产品方向与每阶段优先级
  • 接口仲裁（业务层）与节奏推进
  • 对外演示、汇报、需求变更管理

不负责

  • ERD、状态机、CI/CD 等技术设计
  • 后端/前端实现与 prompt 细节
  • 具体算法与引擎调参
曲良 Simulation Runtime
负责“把 OASIS 跑成商业讨论引擎的拓扑层”。

曲良是主流程中技术风险最高的一段：如果模拟引擎打不通，Phase 2 就没有真正的产品心跳。这里的重点是拓扑、推荐和事件流，而不是商业动作语义本身。

主要负责

  • OASIS 本地跑通与源码理解
  • 交互拓扑与推荐 / 曝光机制
  • 事件流与 trace schema 产出

主要输出

  • `simulation_engine.run(...)` 接口
  • 拓扑 / 推荐机制说明
  • Run 事件流与 trace 数据
  • Quick / Standard / Deep 性能验证
Weiyou Liu Agent Modeling
负责“把商业想法转成可模拟的市场对象”。

Weiyou 接住的是最上游的业务语义：先把用户输入变成 Seed，再把 Seed 变成可运行的 Agent 实例池，同时定义 Agent 之间交互的商业语义动作。

主要负责

  • Seed Materials 生成
  • 8 类 Agent 模板与分布策略
  • 商业语义动作定义
  • 行为先验与 profile 生成

主要输出

  • SeedMaterial JSON
  • AgentInstance JSON
  • semantic actions / behavior hints / system prompt 输入
Chris Platform / Infra
负责“把所有模块装进同一个可维护骨架”。

Chris 是技术中枢。别人关心“做什么”，Chris 需要关心这些东西如何共享数据、如何进入状态机、如何稳定运行。

主要负责

  • 统一 ERD 与 Run 状态机
  • LLM 网关、WebSocket、类型同步
  • 部署、CI、后端骨架治理

主要输出

  • 统一数据模型与迁移链
  • WebSocket / OpenAPI / 状态机接口
  • I1–I7 技术契约初稿
Zhidong Li Explainability / Visualization
负责“让模拟结果看得见、看得懂、讲得出去”。

Zhidong 是主流程的下游消费者，也是最终用户能否感知价值的关键：没有可解释、可展示的表面，再好的模拟也难以形成产品说服力。

主要负责

  • Simulation Live / Report / Agent Chat 前端
  • 报告生成与商业框架映射
  • 可信度指标与行为归因可视化

主要输出

  • 讲解型前端页面与 demo 表面
  • 报告 JSON schema（与 Weiyou 对齐语义口径）
  • 可解释性与商业语义需求反向输入给曲良 / Weiyou
03 / Interfaces

7 个关键协作接口

团队是否顺畅，最终不取决于“谁更努力”，而取决于这些接口是否稳定。尤其要优先打通 I3、I4、I5。

I1用户输入

结构化用户输入 schema

Zhidong + Weiyou 定义，Weiyou 消费。目的是把“商业想法”变成后续可处理的标准输入。

Owner：Zhidong + Weiyou Consumer：Weiyou
I2Seed

SeedMaterial JSON schema

Weiyou 负责定义，曲良和 Zhidong 同时消费：一个用于初始化讨论，一个用于前端展示。

Owner：Weiyou Consumer：曲良 + Zhidong
I3Agent 池

AgentInstance schema

这是最关键的上游接口。只要 Agent 池字段和语义动作字段稳定，Weiyou 和曲良 就可以高度并行。

Owner：Weiyou Consumer：曲良 重点：最关键接口之一
I4状态机

Run 状态机 + 事件类型

Chris + 曲良 共同定义，全员消费。它决定整条链路如何从 pending 一路流转到 completed；事件里的业务语义标签则引用 Weiyou 的动作词典。

Owner：Chris + 曲良 Consumer：全员 重点：最关键接口之一
I5Trace

Trace schema

曲良 + Zhidong 共同定义。没有稳定 trace，报告、可解释性和回放视图都会反复返工；必要时要引用 Weiyou 的语义标签，避免报告解释失真。

Owner：曲良 + Zhidong Consumer：Zhidong 重点：最关键接口之一
I6Report

报告 JSON schema

Zhidong 主笔，但要和 Weiyou 对齐商业语义与框架映射口径；这是 Phase 3 价值呈现的落点。

Owner：Zhidong + Weiyou Consumer：Zhidong
I7LLM Router

LLM 模型路由契约

Chris 负责定义三层模型路由接口，曲良和 Weiyou 根据调用场景指定 core / community / edge。它是成本控制和工程一致性的交汇点。

Owner：Chris Consumer：曲良 + Weiyou
04 / Timeline

6 周推进节奏

每一周都应该能讲清楚一个“对外可感知的进展”，而不是只有内部代码量增长。

W1Phase 1 收口

接口对齐 + OASIS 预验证

  • Yifu：主持接口对齐会，明确 Phase 2 优先级。
  • 曲良：跑通 OASIS 原生 demo，草拟拓扑 / 推荐机制 v0。
  • Weiyou：完成 Seed 后端、起草 Agent 池 schema + 商业语义动作词典。
  • Chris：统一 ERD + 状态机 v0。
  • Zhidong：完成 Seed 前端并调研可解释性方法。
里程碑：Phase 1 收口准备完成
W2Phase 1 Demo

从用户输入到 Seed 页面

  • Phase 1 要求：用户描述想法后，能看到结构化 Seed 结果。
  • 曲良开始把 Reddit 模式改成适合商业讨论的推荐拓扑与曝光机制。
  • Weiyou：定稿第一版商业语义动作集，并接入 Agent 池。
  • Chris 打通 WebSocket 最小版本和类型同步链路。
  • Zhidong 做 Simulation Live mock 页，先不等真实引擎，并和 Weiyou 对齐报告语义口径。
里程碑：完成第一次可讲解 demo
W3–W4Phase 2

模拟真正跑起来

  • 曲良：推荐算法、trace 写入、真实事件流。
  • Weiyou：补齐 8 类角色与三层分级，并和 Zhidong 对齐商业语义 → 报告框架映射。
  • Chris：引擎接入状态机，稳定 WebSocket 与成本统计。
  • Zhidong：接真实事件流，打磨 Live 体验与可信度指标。
里程碑：点击“开始模拟”可以看到实时讨论
W5–W6Phase 3

报告、追问与完整闭环

  • 曲良：复用 trace 和人设做 Agent Chat 后端。
  • Weiyou：补强 behavior hints 与商业语义标签，以支持报告结论。
  • Chris：011 路由 / WebSocket / Docker 准备。
  • Zhidong：报告页、聊天页、可解释摘要落地，并沿用与 Weiyou 对齐后的商业语义口径。
里程碑：完整流程 + 报告 + Agent 追问
05 / Risks

主要风险与应对

这部分适合在团队讲解时单独强调：我们不是没风险，而是提前知道风险在哪里、由谁拍板、如何降级。

高曲良 / Yifu / Chris

OASIS 适配超预期

  • 影响：Phase 2 可能整体后延 1–2 周。
  • 应对：曲良先写 mock engine 解耦下游，Chris 视情况支援。
  • 拍板：Yifu 决定何时启动降级方案。
中Chris + Yifu

接口反复变更

  • 影响：Zhidong 的前端和报告逻辑会反复返工。
  • 应对：Chris 主笔技术定义，Yifu 把关业务优先级，所有变更留 changelog。
中Zhidong + Weiyou

商业语义与报告框架脱节

  • 影响：Phase 3 可能出现“有图无义”或同一术语前后不一致。
  • 应对：Weiyou 和 Zhidong 提前对齐语义词典、报告字段与框架映射，I6 留版本记录。
中Yifu

远程协作效率低

  • 影响：信息只留在口头里，下游不知道上游变了什么。
  • 应对：每周五站会 + 接口文档化 + 以异步记录为主。
中Chris

LLM 成本超预期

  • 影响：Deep 模式定价和交付时延难以成立。
  • 应对：community 层优先用更轻模型兜底，Phase 4 再考虑更重的优化策略。
低全员

边界重新调整

  • 影响：随着实现推进，职责可能继续细化。
  • 应对：把这份页面当成“当前版本”，允许按里程碑迭代，而不是一锤定音。
一句话收尾： 这套分工的关键，不在于把工作平均分掉，而在于让 Weiyou → 曲良 → Zhidong 形成稳定主链， 同时让 Weiyou ↔ Zhidong 在商业语义上持续对齐，让 Chris 负责技术骨架，Yifu 负责方向与节奏。只要接口稳定，5 个人就能真正并行，而不是互相等待。
