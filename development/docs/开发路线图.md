## 0. 设计原则

1. **用户旅程驱动**：每个 Phase 交付一个完整的用户可感知闭环，不做后端孤岛
2. **前后端协同**：每个功能同时交付 API + UI，用户随时可通过浏览器体验
3. **增量可演示**：每个 Phase 结束都能向投资人/用户展示可运行的 Demo
4. **Mock 渐进替换**：前端已有 14 页 mock UI，按优先级逐步替换为真实数据
5. **垂直切片优先**：先做一条完整的端到端路径（输入→模拟→报告），再横向扩展

## 2. 核心用户旅程

**BizSim 的核心价值路径**（一个用户从头到尾的完整故事）：

```
① 描述想法      ② 确认结构化信息    ③ 等待生成       ④ 观看模拟          ⑤ 阅读报告
   用户输入 →      AI 补全 + 用户 →    种子 + Agent →    实时 Agent →        结构化分析
   商业描述        确认/调整            自动生成          对话直播             + 追问对话
```

展开后的详细旅程：

```
用户打开浏览器
  │
  ├─ 看到 Dashboard / 项目列表
  │
  ▼
Step 1: 创建项目 (输入想法)
  │  用户填写：产品名称、一句话描述
  │  可选：产品类型、目标市场、定价、竞品
  │  AI 辅助补全缺失字段
  │
  ▼
Step 2: 配置模拟 (选择场景)
  │  选择深度：Quick(20人) / Standard(100人) / Deep(200人)
  │  确认 Agent 配置预览
  │
  ▼
Step 3: 生成种子材料 (后台 LLM)
  │  系统调用 LLM → 市场上下文、竞品、消费者画像、讨论话题
  │  用户可预览/编辑种子材料
  │
  ▼
Step 4: 生成 Agent 人设 (后台 LLM)
  │  种子材料 + 8 类模板 → 差异化人设
  │  用户可浏览 Agent 列表
  │
  ▼
Step 5: 运行模拟 (OASIS 引擎)
  │  用户点击"开始模拟"
  │  直播间：Agent 对话流 + 指标实时变化
  │
  ▼
Step 6: 查看结果 (报告)
  │  执行摘要 + 市场验证 + 竞品分析
  │  Lean Canvas / SWOT / PMF 评分
  │  风险清单 + 建议
  │
  ▼
Step 7: 追问 Agent (对话)
     选择 Agent → 基于人设+模拟记忆对话
```

## 3. 阶段划分

四个阶段，每阶段交付完整的前后端闭环：

```
Phase 1  输入 → 结构化 → 种子材料        用户可以：描述想法 → 看到 AI 生成的市场分析
           │
Phase 2  Agent 生成 → 模拟 → 实时观看    用户可以：启动模拟 → 实时看 Agent 对话
           │
Phase 3  报告 → 结果展示 → Agent 对话     用户可以：阅读报告 → 追问 Agent
           │
Phase 4  认证 → 支付 → 部署              用户可以：注册付费 → 独立使用
```

## 8. 风险与缓解

| 风险 | 缓解 |
|------|------|
| OASIS 适配难度大 | Quick 模式先验证（20 Agent × 10 轮），备选 Agent-Kernel |
| LLM 成本超预算 | 三层分级 + token 预算 + Batch API |
| 前端改造量大 | 裁剪非核心页面，按 Phase 逐步对接 |
| 模拟结果随机 | 多次取平均 + 标注置信度 + 固定 seed |
| 前后端类型不同步 | MVP 手动同步，后续 OpenAPI 自动生成 |
| MiroFish AGPL 传染 | 参考架构不直接引用代码；长期迁 Agent-Kernel |

## 9. MVP 范围界定
