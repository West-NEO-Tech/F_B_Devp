# Demo 案例 1 - 商业选址（华人超市）

## 1. 这个案例在 Demo 里的作用

这个案例用于展示 **单次模拟能够提供什么信息**。

它不是要证明系统能自动完成全部选址工作，而是要讲清楚：当我们已经准备了一批环境信息和基础假设后，系统如何围绕一个具体商业问题，组织多角色互动，并给出一轮完整、直观、可解释的判断。

这个案例适合做主 Demo，原因有三点：

- 问题足够直观：在某个区开一家华人超市值不值得，几乎所有人都能理解。
- 环境变量容易准备：人口、交通、竞品、租金、消费能力等信息都可以提前整理为 Demo 输入。
- 结果不会天然一边倒：需求可能存在，但租金、竞品、停车、客单价、供应链都可能成为阻力，因此更容易展示“模拟为什么有意义”。

---

## 2. 核心问题

> 如果要在墨尔本某个 suburb 开一家面向华人家庭与亚洲食品消费群体的中型社区超市，这个位置是否合适？

这个问题的重点不是抽象地讨论“华人超市有没有市场”，而是回答一个更具体的商业决策：

- **在这个位置开店，需求是否足够强？**
- **主要客群到底是谁？**
- **最大的阻力来自哪里？**
- **这个点位更适合开什么样的店，而不是简单地开或不开？**

---

## 3. 故事设定

一个创业者计划在墨尔本一个亚洲家庭和留学生增长较快的 suburb 开一家中型华人社区超市。

他不是要做大型卖场，而是想做一家更贴近社区生活的门店，主打：

- 新鲜蔬菜与水果
- 亚洲调味品和干货
- 冷冻食品与熟食半成品
- 节日型或家庭型采购需求

他的初步想法是：

- 门店规模中等
- 以家庭复购为核心
- 兼顾附近学生与年轻上班族
- 价格略低于精品亚洲超市，但高于纯折扣店

他现在最关心的不是“有没有人爱吃亚洲食品”，而是：

- 这个区到底有没有足够密度的目标客群
- 周边已有竞品是否太强
- 这个位置的便利性是否足以支撑复购
- 如果真的开，是做“家庭补货型社区店”还是“学生速购型小店”更合理

---

## 4. Demo 里需要提前准备什么

这个案例里，很多环境变量可以提前准备好，不需要现场解释这些信息是怎么来的。只要把它们视作 Demo 已准备好的背景输入即可。

### 4.1 基础项目输入

这些输入由用户或演示者在最前面明确：

- 城市：Melbourne
- 目标 suburb：选择 1 个具体区域（例如东南方向、学生与家庭混合社区）
- 商业类型：中型社区华人超市
- 目标客群：华人家庭、亚洲食品稳定消费群体、留学生、附近上班族
- 门店定位：社区补货 + 周末集中采购
- 价格带：中等偏平价
- 初步经营模式：线下门店为主，可带少量线上预订/社群团购能力

### 4.2 需要提前准备的环境信息

建议把这些信息整理成一份固定的“环境资料包”：

- 区域人口规模
- 家庭结构（单身、家庭、有孩家庭）
- 亚洲背景居民或亚洲食品高频消费群体的 proxy 信息
- 学生人口与租房人口占比
- 收入水平与消费能力
- 车流、人流、停车条件
- 公共交通便利度
- 周边住宅密度和学校分布
- 商铺租金区间
- 周边已有超市、亚洲超市、生鲜店分布
- 现有竞品的价格带、品类优势与位置优势
- 供应链可达性（批发、进口、配送便利度）

### 4.3 可选的额外输入

这些输入不是必须，但如果提前准备，会让模拟更像真实商业决策：

- 预计店铺面积
- 预计日常 SKU 数量级
- 是否包含熟食/热食
- 是否支持外卖平台或团购群
- 初步租约条件
- 开店预算的上限区间

---

## 5. 多角色设置（核心部分）

这个案例的重点是 **多角色交互**，而不是单一市场分析。因此需要把角色设计得足够贴近现实，但又不能过多过杂。

建议主交互围绕以下 6 类角色展开：

| 角色类型 | 代表对象 | 最关心的问题 | 在模拟中的作用 |
|---|---|---|---|
| 消费者 Agent | 华裔家庭、亚洲食品消费者、学生、年轻上班族 | 买不买、多久买一次、为什么来/不来 | 提供真实需求、复购、价格敏感度 |
| 竞品 Agent | 附近亚洲超市、主流连锁超市、生鲜店 | 会不会被分流、如何应对 | 提供竞争强度和替代压力 |
| 供应商 Agent | 批发商、进口分销商、生鲜供应链 | 供货稳定性、成本、品类能力 | 决定品类丰富度与毛利空间 |
| 房东/场地方 Agent | 商铺业主或商圈管理方 | 租金、租约、客流、物业条件 | 决定选址成本和约束 |
| 社区影响者 Agent | 社区群组织者、本地 KOL、熟人网络 | 会不会推荐、是否形成口碑 | 决定早期传播效率 |
| 监管/规则 Agent | 食品安全、营业规范、停车与营业时间约束 | 合规风险、运营限制 | 决定是否存在隐藏阻力 |

如果需要更完整一些，可以再加入 1 类 **导师/观察者 Agent**，用于在汇总阶段给出更宏观的商业判断，但不建议让它在主交互中抢戏。

---

## 6. 这些角色之间要怎么互动

这个案例最重要的不是角色列表，而是这些角色之间的相互影响关系。

### 6.1 第一层互动：消费者内部的需求分化

不同消费者对这个超市的期待并不一样：

- 家庭型用户更关注稳定供应、停车便利、大包装、蔬果质量
- 学生用户更关注价格、便利性、小包装与即食性
- 年轻上班族更关注晚间可达性、周末采购效率与线上预订

因此第一层互动，不是“大家会不会来”，而是：

- **谁会来**
- **为什么来**
- **谁虽然有需求，但不会形成稳定复购**

### 6.2 第二层互动：消费者与竞品的比较

消费者会自然把这个新店与现有选择做比较：

- 如果价格不明显更优，为什么不去已有大超市？
- 如果品类不够全，为什么不去更成熟的亚洲超市？
- 如果停车麻烦，为什么要专门过来？
- 如果只是买少量调料，为什么不顺路在别的店完成？

因此竞品 Agent 的作用不是简单说“有竞争”，而是要推动一个更真实的问题：

> 新店到底靠什么把人从现有购买路径里拉出来？

### 6.3 第三层互动：供应商与店型可行性

供应商不会直接决定消费者需求，但会影响：

- 能不能稳定供货
- 能不能做出差异化品类
- 毛利空间是不是足够
- 哪些品类适合做主打，哪些不适合

这会反过来影响消费者体验：

- 如果品类不稳定，消费者不会形成复购
- 如果爆款商品缺货，早期口碑会很差
- 如果成本过高，价格就会变得没有优势

### 6.4 第四层互动：房东/位置条件与真实转化

很多“看起来有需求”的位置，最终问题可能并不在需求，而在现实经营条件：

- 租金是否吃掉利润空间
- 停车是否足够方便
- 门头可见性强不强
- 周边动线是否支持顺路购买

这类变量很适合在模拟中与消费者行为交叉：

- 有人愿意来，但只愿意周末来
- 有人觉得产品不错，但不会形成高频到店
- 有人愿意推荐，但实际转化受位置条件限制

### 6.5 第五层互动：社区传播

社区型生意并不是单靠广告驱动，它很大程度上依赖：

- 家庭社群的推荐
- 留学生朋友圈口碑
- 社区群消息扩散
- 节日采购的临时爆发

这类互动特别适合展示“为什么多角色模拟比静态分析更有意思”：

- 有些需求不是广告调研能直接问出来的
- 有些门店不是靠第一次到店，而是靠被熟人网络带动

## 7. 这个案例的模拟思路

这个案例建议按照 **单次模拟** 来设计，但模拟内部依然可以分阶段推进。

### 阶段 1：输入项目与固定环境

先明确：

- 店开在哪里
- 想卖给谁
- 想做什么类型的店
- 有哪些现成的环境背景

这一步不强调通用能力，而强调 Demo 的“场景包”已经准备好。

### 阶段 2：生成贴合该区的角色

根据环境资料，生成一组贴合本地的 Agent：

- 家庭型买菜用户
- 学生型临时补货用户
- 有车周末采购用户
- 对价格高度敏感的消费者
- 已经习惯现有竞品的忠诚顾客
- 能影响社区传播的人群

### 阶段 3：让角色围绕“是否会使用这家店”展开互动

建议不要把模拟做得过分宏大，而是聚焦几个核心问题：

- 第一印象：这家店吸不吸引人？
- 到店门槛：位置和交通会不会劝退？
- 替代方案：为什么不去现有店？
- 复购动力：什么情况下会形成固定采购？
- 口碑传播：什么情况下会推荐给别人？

### 阶段 4：归纳为商业判断

最后不是输出“对/错”，而是形成三种可能的判断之一：

- **值得做**：这个区确实有足够强的需求与传播潜力
- **可以做，但要改店型**：例如更适合做社区补货店，而不是大而全超市
- **不建议做**：不是没有需求，而是竞品、租金、动线等现实约束让它不成立

---

## 8. 单次模拟应该重点产出什么

这个案例的输出不应该只是一个分数，而应该回答这些直观问题：

- 这个位置的综合可行性如何？
- 哪 2-3 类客群最值得抓？
- 消费者最强的吸引因素是什么？
- 消费者最强的劝退因素是什么？
- 现有竞品的真正优势是什么？
- 如果要做，应该做成什么样的店？
- 如果不做，主要死因是什么？

建议现场展示时，把结果收敛成下面几个板块：

- **需求强度**
- **竞争压力**
- **位置便利性**
- **复购潜力**
- **经营风险**
- **建议店型 / 建议调整方向**

---

## 9. 这个案例在展示时最值得强调的点

这个案例的价值，不是“系统告诉你华人超市有需求”，而是：

> 系统能把一个非常直观的选址问题，拆成多角色、多约束、多轮影响的商业判断。

现场讲解时，最值得强调的是：

1. **同样是“开华人超市”，不同位置的判断完全不同。**
2. **需求存在，不代表这个点位成立。**
3. **最后真正决定结果的，可能不是需求本身，而是租金、停车、动线或竞品强度。**
4. **模拟的意义在于让“为什么成立 / 为什么不成立”变得可解释。**

---

## 10. 适合作为 Demo 的一句话总结

> 这是一个围绕“具体位置能不能开、该开什么样的店”展开的单次模拟案例。它最适合展示：当环境信息被准备好之后，系统如何通过多角色互动，把一个直观但复杂的商业问题讲清楚。
